MENGAPA LOCAL STORAGE?
Local storage memungkinkan aplikasi menyimpan data di device pengguna. Data tetap tersedia meskipun aplikasi ditutup atau
tidak ada koneksi internet.
Keuntungan Local Storage:
Faster Access Data tersedia instan tanpa network latency
Offline Support Aplikasi tetap berfungsi tanpa internet
Data Persistence Data tetap ada setelah app ditutup
Battery Efficient Tidak perlu radio untuk network requests
Reduce Data Usage Hemat kuota dengan caching

DATASTORE
PREFERENCES
Key-Value Storage untuk Settings
APA ITU DATASTORE?
DataStore adalah solusi modern untuk menyimpan data key-value. Menggantikan SharedPreferences dengan API yang lebih
aman menggunakan Kotlin Coroutines dan Flow.
DataStore vs SharedPreferences:
SharedPreferences
• Synchronous API (blocking)
• No type safety
• No error handling
• Can cause UI jank
• No multiplatform support
✓ DataStore
• Asynchronous with Coroutines
• Type-safe with Proto/Preferences
• Built-in error handling
• Main thread safe
• KMP support (with libraries)

import com.russhwolf.settings.Settings
import com.russhwolf.settings.get
import com.russhwolf.settings.set
class SettingsManager(private val settings: Settings) {

 companion object {
 private const val KEY_THEME = "app_theme"
 private const val KEY_LANGUAGE = "app_language"
 private const val KEY_ONBOARDING = "onboarding_complete"
 private const val KEY_AUTH_TOKEN = "auth_token"

}

 // Theme: "light", "dark", "system"
 var theme: String
 get() = settings[KEY_THEME, "system"]
 set(value) { settings[KEY_THEME] = value }

 var language: String
 get() = settings[KEY_LANGUAGE, "en"]
 set(value) { settings[KEY_LANGUAGE] = value }

 var isOnboardingComplete: Boolean
 get() = settings[KEY_ONBOARDING, false]
 set(value) { settings[KEY_ONBOARDING] = value }

 var authToken: String?
 get() = settings.getStringOrNull(KEY_AUTH_TOKEN)
 set(value) {
 if (value != null) settings[KEY_AUTH_TOKEN] = value
 else settings.remove(KEY_AUTH_TOKEN)

}
}

Type-Safe SQL Database untuk KMP
APA ITU SQLDELIGHT?
SQLDelight adalah library dari Square/CashApp yang generates type-safe Kotlin APIs dari SQL statements. Mendukung Kotlin
Multiplatform dengan SQLite di semua platform.
Keuntungan SQLDelight:
✓ Type-Safe Compile-time verification untuk SQL queries
✓ SQL First Write real SQL, bukan DSL baru
✓ Multiplatform Support Android, iOS, Desktop, Web
✓ Auto-Generated Kotlin code generated dari .sq files
✓ Reactive Built-in support untuk Flow

REPOSITORY DENGAN SQLDELIGHT
NoteRepository.kt
class NoteRepository(private val database: NotesDatabase) {

 private val queries = database.queries

 // Get all notes as Flow
 fun getAllNotes(): Flow<List<Note>> {
 return queries.selectAll()
 .asFlow()
 .mapToList(Dispatchers.IO)
 }

 // Get note by ID
 suspend fun getNoteById(id: Long): Note? {
 return withContext(Dispatchers.IO) {
 queries.selectById(id).executeAsOneOrNull()
 }
 }

 // Insert note
 suspend fun insertNote(title: String, content: String) {
 val now = Clock.System.now().toEpochMilliseconds()
 withContext(Dispatchers.IO) {
 queries.insert(title, content, now, now)
 }
 }

 // Update note
 suspend fun updateNote(id: Long, title: String, content: String) {
 val now = Clock.System.now().toEpochMilliseconds()
 withContext(Dispatchers.IO) {
 queries.update(title, content, now, id)
 }
 }

 // Delete note
 suspend fun deleteNote(id: Long) {
 withContext(Dispatchers.IO) {
 queries.delete(id)
 }
 }
}

Caching dan Sync Strategies
OFFLINE-FIRST ARCHITECTURE
Offline-first berarti aplikasi selalu menggunakan local database sebagai sumber utama data. Network hanya untuk sync. User experience tetap
smooth meskipun tanpa koneksi.
Data Flow:
UI
(Compose) → Repository
→
→
Local DB
(Primary)
Remote API
(Sync)
← Sync
1. UI reads from Local DB (always available)
2. Repository syncs with Remote API in background
3. Changes pushed to Local DB → UI auto-updates via Flow
Pengembangan Aplikasi Mobile - ITERA 22/40
CACHING STRATEGIES
Cache First
Baca dari cache dulu, fetch jika expired
Use: Static content, user profiles
Network First
Fetch dari network, fallback ke cache
Use: News, real-time data
Stale While Revalidate
Return cache, update di background
Use: Feed, lists
Cache Only
Hanya dari cache, no network
Use: Offline-only features

class NoteRepository(
 private val localDataSource: NoteLocalDataSource,
 private val remoteDataSource: NoteRemoteDataSource
) {
 fun getNotes(): Flow<List<Note>> {
 return localDataSource.getAllNotes()
 .onStart {
 // Sync dengan server di background
 refreshFromNetwork()

}

}

 private suspend fun refreshFromNetwork() {
 try {
 val remoteNotes = remoteDataSource.fetchNotes()
 localDataSource.insertAll(remoteNotes)
 } catch (e: Exception) {
 // Network error
- gunakan data lokal
 // Log error tapi tidak throw ke UI

}

}

 suspend fun addNote(note: Note) {
 // Simpan ke lokal dulu (optimistic update)
 localDataSource.insert(note)

 // Sync ke server di background
 try {
 remoteDataSource.createNote(note)
 } catch (e: Exception) {
 // Mark as pending sync
 localDataSource.markPendingSync(note.id)

}

}
}

CachedNewsRepo.kt
class CachedNewsRepository(
 private val api: NewsApi,
 private val db: NewsDatabase
) {
 fun getNews(): Flow<List<Article>> {
 return db.articleQueries.selectAll()
 .asFlow()
 .mapToList()
 .onStart { refreshFromNetwork() }
 }

 private suspend fun refreshFromNetwork() {
 try {
 val articles = api.getTopHeadlines()
 db.transaction {
 db.articleQueries.deleteAll()
 articles.forEach {
 db.articleQueries.insert(it)
 }
 }
 } catch (e: Exception) {
 // Use cached data
 }
 }
}
